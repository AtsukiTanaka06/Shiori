# Test Skill

テストを作成・実行します。

## 判断基準

### Unit Test が必要な場合
- ビジネスロジック（ステータス判定、バリデーション）
- ユーティリティ関数（日付フォーマット、ISBN 変換等）
- 型変換・マッピング（API レスポンス → Book モデル）
- Zustand ストアのロジック

### Integration Test が必要な場合
- Supabase とのデータ操作
- 書籍 API とのやり取り
- 認証フロー

### E2E Test が必要な場合
- 主要ユースケース（バーコード登録・検索登録・本棚表示）

## 実行手順

1. テスト計画を立てる
2. テストを実装する
3. `npm test` で実行
4. 失敗した場合は原因を分析して修正
5. `npx tsc --noEmit` で型チェック

## テスト命名

```typescript
test('〇〇の場合、〇〇になること', () => { ... })

describe('対象機能', () => {
  it('具体的なケース', () => { ... })
})
```
