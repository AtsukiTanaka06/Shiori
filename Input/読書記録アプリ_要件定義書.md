# 読書記録アプリ 要件定義書

## 1. 概要

本を読んだ記録を残し、自分の読書履歴を本棚として管理・振り返るためのiPhoneアプリ。

主な登録方法として「本のバーコード読み取り」と「タイトル・著者・ISBNなどによる検索」を提供する。

本の書籍情報と、自分自身の読書記録を分けて管理する。

---

## 2. スコープ

### 2.1 MVPで実装する機能

- 本のバーコード読み取りによる登録
- タイトル・著者・ISBNによる書籍検索
- 書籍情報の取得・表示
- 読書記録の登録
- 読書ステータスの管理
- 本棚一覧表示
- 本棚の表示形式切り替え
- ステータスによる絞り込み
- 本の詳細表示
- 本の編集
- 本の削除

### 2.2 アカウント・データ同期

機種変更時にも読書記録を引き継げるよう、ユーザーアカウントを利用して読書データをクラウドに保存する。

- ユーザー登録・ログイン
- ログアウト
- アカウント削除
- 読書データをユーザーアカウントに紐付け
- 機種変更後のデータ引き継ぎ
- ユーザーごとのデータ分離

認証基盤およびクラウドDBにはSupabaseを利用する。

### 2.3 MVPでは対象外

- 同一書籍の再読管理
- AIによる感想分析・要約
- SNS・ソーシャル機能
- 読書目標
- 高度な読書統計
- 課金機能

## 3. ユースケース

### UC-01：バーコードから本を登録する

1. 本棚画面から「本を追加」を選択
2. バーコードスキャンを選択
3. 本のバーコードを読み取る
4. ISBNを取得
5. ISBNを利用して書籍情報を検索
6. 書籍情報を表示
7. 必要に応じて書籍情報を確認・編集
8. 読書情報を入力
9. 本を登録する

### UC-02：書籍を検索して登録する

1. 本棚画面から「本を追加」を選択
2. 本の検索を選択
3. タイトル、著者、ISBNなどを入力
4. 書籍を検索
5. 検索結果から本を選択
6. 書籍情報を表示
7. 読書情報を入力
8. 本を登録する

### UC-03：登録した本を確認する

1. 本棚画面を開く
2. 登録済みの本を一覧で確認
3. 本を選択
4. 本の詳細情報を確認する

### UC-04：読書記録を編集する

1. 本の詳細画面を開く
2. 編集を選択
3. 書籍情報・読書情報を編集
4. 保存する

### UC-05：本を削除する

1. 本の詳細画面を開く
2. 削除を選択
3. 削除確認
4. 本を削除する

### UC-06：アカウントを作成・ログインする

1. アプリを初回起動
2. ログイン画面を表示
3. 認証方法を選択
4. アカウントを作成またはログイン
5. 本棚を表示する

### UC-07：機種変更後に読書データを引き継ぐ

1. 新しいiPhoneにアプリをインストール
2. 既存アカウントでログイン
3. Supabaseからユーザーの読書データを取得
4. 以前の本棚を復元する

### UC-08：ログアウトする

1. 設定画面を開く
2. ログアウトを選択
3. ログアウトする

### UC-09：アカウントを削除する

1. 設定画面を開く
2. アカウント削除を選択
3. 削除確認
4. アカウントおよびユーザーに紐付くデータを削除する

## 4. 書籍情報

書籍情報として以下を管理する。

| 項目 | 必須 | 備考 |
|---|---|---|
| 表紙画像 | ○ | 書籍APIから取得 |
| タイトル | ○ |  |
| 著者 | ○ |  |
| ISBN | ○ | ISBN-10 / ISBN-13を想定 |
| 出版社 | △ | APIから取得できる場合 |
| 発売日 | △ | APIから取得できる場合 |
| ページ数 | △ | APIから取得できる場合 |
| ジャンル | △ | APIから取得できる場合 |

※「△」は取得できる場合に保持する任意情報。

## 5. 読書記録

書籍情報とは別に、ユーザー自身の読書記録を管理する。

| 項目 | 必須 | 備考 |
|---|---|---|
| ステータス | ○ | 「これから」「読了」 |
| 読み始め | × | 任意入力 |
| 読み終わり | × | 任意入力 |
| 評価 | × | 5段階 |
| 感想 | × | 任意入力 |
| メモ | × | 任意入力 |
| 登録日時 | ○ | 自動記録 |

### 5.1 ステータス

ステータスは以下の2種類。

- **これから**：まだ読んでいない本
- **読了**：読み終わった本

「読書中」はステータスとして設けない。

ステータスはユーザーが変更可能とする。

### 5.2 読書開始日・読了日

読み始め・読み終わりはどちらも任意入力。

そのため、例えば以下の状態を許容する。

- 「これから」かつ日付未入力
- 「読了」だが読み始め・読み終わりが未入力
- 「読了」で読み始めのみ入力
- 「読了」で読み始め・読み終わりの両方を入力

日付が未入力でも登録・編集できる。

### 5.3 評価

5段階評価。

- ★☆☆☆☆
- ★★☆☆☆
- ★★★☆☆
- ★★★★☆
- ★★★★★

評価なしも許可する。

### 5.4 感想

本を読んだ後のレビュー・感想を記録する。

### 5.5 メモ

読書中や読後に自由に残すメモ。

感想とは別項目として管理する。

## 6. 再読

MVPでは再読をスコープ外とする。

基本的に、

> 1冊の登録済み書籍 = 1つの読書記録

として扱う。

同一ISBNの再読履歴を複数保持する機能は実装しない。

---

## 7. 本棚

登録済みの本を本棚として表示する。

### 7.1 表示形式

2種類の表示形式を提供する。

#### リスト表示

以下を表示する。

- 表紙
- タイトル
- 著者

例：

```text
[表紙] 嫌われる勇気
       岸見一郎

[表紙] 7つの習慣
       スティーブン・R・コヴィー
```

#### 表紙表示

表紙画像のみをグリッド形式で表示する。

タイトルや著者は一覧上では表示しない。

### 7.2 表示形式の切り替え

本棚画面から、

- リスト表示
- 表紙表示

を切り替えられるようにする。

### 7.3 デフォルトの並び順

本棚のデフォルトの並び順は、

> 登録日時の新しい順

とする。

### 7.4 ステータスによる絞り込み

本棚ではステータスによる絞り込みを可能にする。

フィルター：

- すべて
- これから
- 読了

デフォルトは「すべて」。

フィルター適用後も基本の並び順は登録日時の新しい順とする。

## 10. バーコードスキャン

バーコードからISBNを取得し、書籍情報を検索する。

### 想定フロー

```text
バーコードスキャン
        ↓
バーコード認識
        ↓
ISBN取得
        ↓
書籍API検索
        ↓
書籍情報表示
```

### エラー時

以下の場合を考慮する。

- カメラ権限が許可されていない
- バーコードを読み取れない
- ISBNから書籍が見つからない
- API通信に失敗する

ISBNから書籍が見つからない場合は、検索画面または手動検索へ移行できるようにする。

## 13. アカウント・データ同期

### 13.1 アカウント

読書記録を機種変更後も引き継げるよう、ユーザーアカウントを利用する。

認証基盤には **Supabase Auth** を利用する。

認証方式は技術設計時に決定するが、iPhoneアプリでの利用を想定し、Appleでのサインインを第一候補とする。

### 13.2 データ保存

読書データはSupabase PostgreSQLに保存する。

```text
iPhoneアプリ
    ↓
Supabase Auth
    ↓
ユーザーID
    ↓
Supabase PostgreSQL
    ↓
読書データ
```

### 13.3 ユーザーごとのデータ分離

ユーザーが自分自身のデータだけを参照・変更できるよう、SupabaseのRow Level Security（RLS）を利用する。

### 13.4 機種変更

同じアカウントで新しいiPhoneにログインすることで、以前の読書記録を取得できるものとする。

### 13.5 アカウント削除

アカウント削除時には、ユーザーに紐付く読書記録などの個人データも削除する。

## 13. データモデルの基本方針

書籍情報と読書記録を論理的に分離する。

### Book

書籍そのものの情報。

```text
Book
├── id
├── isbn
├── title
├── authors
├── coverImage
├── publisher
├── publishedAt
├── pageCount
└── genre
```

### ReadingRecord

ユーザーの読書記録。

```text
ReadingRecord
├── id
├── userId
├── bookId
├── status
├── startedAt
├── finishedAt
├── rating
├── impression
├── memo
└── createdAt
```

`userId` により、読書記録をユーザーアカウントに紐付ける。

再読はスコープ外のため、MVPでは1つのBookに対して1つのReadingRecordを基本とする。

## 14. エラー・例外処理

最低限、以下を考慮する。

### バーコード

- カメラ権限拒否
- 読み取り失敗
- 不正なバーコード
- ISBN取得失敗

### 書籍検索

- 書籍が見つからない
- API通信エラー
- 表紙画像が存在しない
- 書籍情報の一部が存在しない

### 登録

- 二重登録
- 登録処理失敗

二重登録時には、既に登録済みであることをユーザーに通知する。
